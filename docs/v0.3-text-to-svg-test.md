## Accepted v1 gate

The agreed v1 gate covers the two product modes that define scope A+B:

1. **Icon / Logo mark** — text-free, simple/limited-palette vector output;
2. **Vector Illustration** — multi-object flat illustration with a larger palette.

The gate also requires transparent-background handling plus the complete user-visible SVG lifecycle: Download SVG, View source, Reuse and Delete.

A larger four-sample stress matrix remains useful as follow-up QA, but it is no longer a blocker for the agreed v1 product acceptance because the two representative product modes and lifecycle were exercised successfully on target hardware.

The first physical attempt exposed a real compatibility bug: VTracer emits a standard root `version="1.1"` attribute while the initial Clean SVG sanitizer rejected every `version` attribute. The issue was reproduced with RED CI coverage and fixed so only SVG `1.0` / `1.1` are accepted as input metadata and stripped from the canonical final SVG. Exact-head Actions #871 passed 288 Python tests, 248 Pester tests, package build and artifact upload on commit `5782771a9da306e60ec01caaed5fc40a00165825`.

The physical log recorded a Z-Image prompt execution time of `254.27 s` for the original failing attempt; the failure happened after raster generation, at SVG sanitization, not in the GPU generation path.

## Clean SVG / safety acceptance

The physical outputs reached the full local pipeline:

```text
Z-Image raster
  -> release GPU runtime
  -> optional border-connected background removal
  -> VTracer
  -> Clean SVG sanitizer
  -> resvg_py preview
  -> persisted SVG + Gallery record
```

The accepted sanitizer contract remains unchanged apart from the explicit VTracer root-version compatibility rule. Active/unsupported content such as script, embedded raster image, text, external href/URL, event handler, DTD/entity and unknown namespace remains forbidden.
