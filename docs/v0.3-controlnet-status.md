# StableAMD v0.3 — ControlNet / structural guidance status

Last updated: 2026-09-15

## Current state

ControlNet development is now prioritized for **Z-Image Turbo and Krea 2 Turbo**. SDXL is not the feature-development target for this phase.

The first implementation layer is in the branch and keeps all previously accepted generation paths behind a preserved product-server compatibility layer.

Automated baseline: **GitHub Actions #589 — GREEN** end to end after the ControlNet composition was added. The run passed PowerShell parsing, Python API/regression tests, Pester tests, source package build and artifact upload.

### Z-Image Turbo — Canny

Implementation status: **implemented, target gate pending**.

Route:

```text
LoadImage
  -> ImageScale
  -> Canny (core pinned ComfyUI node)
  -> ZImageFunControlnet.image

UNET / optional model path
  -> ZImageFunControlnet + Union 2.1 Lite patch
  -> ModelSamplingAuraFlow
  -> KSampler
```

Dependencies:

- existing accepted `Z-Image-Turbo-Fun-Controlnet-Union-2.1-lite-2602-8steps.safetensors`;
- pinned ComfyUI core `Canny` node;
- existing native `ModelPatchLoader` + `ZImageFunControlnet` nodes.

Product controls for the first gate:

- normal source image;
- strength, default `1.0`;
- Canny low threshold, default `0.4`;
- Canny high threshold, default `0.8`.

Regular LoRAs are intentionally blocked only for this first acceptance gate. Composition can be enabled after the base controlled path is proven on target.

### Krea 2 Turbo — OpenPose map

Implementation status: **implemented, dependency install + target gate pending**.

The first Krea 2 Turbo control route intentionally uses components with explicit licenses:

- `ostris/ComfyUI-Krea2-Ostris-Edit`, pinned commit `7756566160c4a1b24bb1bd9f0ff3ced1a83d7547`, MIT;
- `thedeoxen/Krea-2-pose-controlnet/krea2_turbo_openpose_controlnet.safetensors`, Apache-2.0;
- exact adapter size `228587504` bytes;
- exact SHA-256 `0ddc3aafce4abdf7af3309b2f00c1bacdf15df1f2b4fb7adc9ff71795da90ecf`.

The dependency installer clones the exact plugin revision and downloads/verifies the exact adapter. A backend restart is required so ComfyUI registers the custom nodes and LoRA.

First gate input is an **already prepared OpenPose / DWPose skeleton map**. Automatic DWPose extraction is deliberately the next sub-phase instead of silently adding another large custom-node dependency before the core route is accepted.

Graph shape:

```text
LoadImage (pose map)
  -> ImageScale
  -> TextEncodeKrea2OstrisEdit (positive + reference)
  -> KSampler positive

same pose map
  -> TextEncodeKrea2OstrisEdit (empty negative + reference)
  -> KSampler negative

Krea 2 MODEL
  -> Krea2OstrisEditModelPatch
  -> LoraLoaderModelOnly(openpose control adapter)
  -> KSampler model
```

Regular style LoRAs are intentionally blocked only for this first acceptance gate.

## Target acceptance sequence

### Gate C2.1 — Z-Image Canny

1. Update/start StableAMD.
2. Select `Z-Image Turbo`.
3. Enable `Control guidance` and choose `Canny edges`.
4. Upload a normal reference image.
5. Use strength `1.0`, low `0.4`, high `0.8`.
6. Generate with the normal 8-step Z-Image Turbo profile.
7. Confirm the output visibly follows the source edges/structure.
8. Immediately run normal Z-Image txt2img afterwards.

### Gate C3.1 — Krea 2 OpenPose

1. Select `Krea 2 Turbo (FP8)`.
2. If the panel offers `Install dependency`, use it and let StableAMD restart the backend.
3. Enable `Control guidance` and choose `OpenPose map`.
4. Upload an already prepared OpenPose/DWPose skeleton map.
5. Start at strength `0.85`.
6. Use the accepted Krea Turbo defaults (`8 steps / CFG 1 / Euler / simple`).
7. Confirm the generated pose follows the skeleton.
8. Immediately run normal Krea 2 txt2img afterwards.

## Non-regression rule

ControlNet work must not change the accepted behavior of:

- Krea 2 Turbo base generation;
- Krea 2 model-only LoRA;
- Z-Image Turbo base generation;
- Z-Image model-only LoRA;
- Z-Image native inpaint/outpaint;
- classic upscale and Gallery reuse.
