# StableAMD v0.3 — ControlNet / structural guidance status

Last updated: 2026-09-15

## Current state

ControlNet development is prioritized for **Z-Image Turbo and Krea 2 Turbo**. SDXL is not the feature-development target for this phase.

The provider-aware ControlNet layer, Pose Template Library and interactive Pose Editor are now target-tested on the RX 6950 XT / 16 GiB machine.

Automated pose/control baseline: **GitHub Actions #591 — GREEN** end to end. The run passed PowerShell parsing, Python API/regression tests, Pester tests, source package build and artifact upload.

### Krea 2 Turbo — OpenPose map

Implementation status: **target accepted; performance tuning remains open**.

The Krea 2 Turbo control route uses components with explicit licenses:

- `ostris/ComfyUI-Krea2-Ostris-Edit`, pinned commit `7756566160c4a1b24bb1bd9f0ff3ced1a83d7547`, MIT;
- `thedeoxen/Krea-2-pose-controlnet/krea2_turbo_openpose_controlnet.safetensors`, Apache-2.0;
- exact adapter size `228587504` bytes;
- exact SHA-256 `0ddc3aafce4abdf7af3309b2f00c1bacdf15df1f2b4fb7adc9ff71795da90ecf`.

The curated dependency installer clones the exact plugin revision and downloads/verifies the exact adapter. A managed backend restart activates the nodes and LoRA.

Accepted graph shape:

```text
OpenPose map
  -> ImageScale
  -> TextEncodeKrea2OstrisEdit (positive + reference)
  -> KSampler positive

same pose map
  -> TextEncodeKrea2OstrisEdit (empty negative + reference)
  -> KSampler negative

Krea 2 MODEL
  -> Krea2OstrisEditModelPatch(kv_cache=false)
  -> LoraLoaderModelOnly(openpose control adapter)
  -> KSampler model
```

The target test showed the route is functional but materially slower than plain Krea 2. A follow-up experiment enabled the provider-published `kv_cache=true` setting, but on the RX 6950 XT target the next Krea OpenPose run did not reach model sampling and timed out after 900 seconds. The backend log stopped after loading the Krea text encoder and WanVAE. Because the previously accepted `kv_cache=false` path completed successfully, StableAMD reverted the experiment and keeps the accepted non-cached path as the default.

This does not prove that K/V caching itself is the sole cause of the stall; the regression happened immediately after that experiment and no performance benefit was demonstrated on this target. Any future cached-reference work must therefore be isolated behind an explicit experimental option and benchmarked separately.

StableAMD keeps the Qwen3-VL text encoder on CPU by default for the 16 GiB Radeon profile. That preserves the accepted memory-safe baseline; moving the encoder to the default/GPU path remains a separate measured optimization rather than a blind default change.

Regular style LoRAs remain blocked only for the first ControlNet composition gates. They can be re-enabled after the controlled provider paths and their memory/performance behavior are fully accepted.

## Pose Library + interactive editor

Target status: **accepted for both Z-Image and Krea 2 OpenPose**.

- Pose Templates from `a-lgil/pose-depot`, pinned to commit `10471a9df9a5f25fba422e542475e6a72b5f23b8` (Apache-2.0).
- Editable preset source from `andreszs/ComfyUI-OpenPose-Studio`, pinned to commit `4071e2c1259956f219cca617ca8b73c6608e50d5` (MIT).
- Template selection is enough to drive OpenPose; manual file upload is optional.
- Interactive 18-joint editor supports direct pose adjustment, mirror/reset and PNG export.
- Optional reference-photo overlay helps manual alignment and is not baked into the final control map.

## Next ControlNet sub-phases

1. Keep the accepted Krea 2 OpenPose path stable and profile the pre-sampling text/image-conditioning stage without changing graph semantics.
2. Optional automatic DWPose extraction from a normal reference photo.
3. Z-Image depth preprocessing + Union 2.1 depth gate.
4. Krea 2 depth using `Patil/Krea-2-depth-controlnet` once the managed integration/preprocessor path is pinned and license-safe.
5. Krea 2 Canny only after a genuine Turbo-compatible path is validated; RAW-only/experimental routes are not treated as accepted Turbo support.

## Non-regression rule

ControlNet work must not change the accepted behavior of:

- Krea 2 Turbo base generation;
- Krea 2 model-only LoRA;
- Z-Image Turbo base generation;
- Z-Image model-only LoRA;
- Z-Image native inpaint/outpaint;
- classic upscale and Gallery reuse.
