# StableAMD v0.3 — ControlNet / structural guidance status

Last updated: 2026-09-15

## Current state

ControlNet development is prioritized for **Z-Image Turbo and Krea 2 Turbo**. SDXL is not the feature-development target for this phase.

The provider-aware ControlNet layer, Pose Template Library and interactive Pose Editor are target-tested on the RX 6950 XT / 16 GiB machine. Z-Image Canny/OpenPose and the Krea OpenPose execution path are functional. The remaining Krea pose work is framing/performance refinement rather than base-model correctness.

### Krea 2 Turbo — OpenPose map

Implementation status: **functional on target; current compact-reference path requires framing/performance retest**.

Dependencies:

- `ostris/ComfyUI-Krea2-Ostris-Edit`, pinned commit `7756566160c4a1b24bb1bd9f0ff3ced1a83d7547`, MIT;
- `thedeoxen/Krea-2-pose-controlnet/krea2_turbo_openpose_controlnet.safetensors`, Apache-2.0;
- adapter size `228587504` bytes;
- adapter SHA-256 `0ddc3aafce4abdf7af3309b2f00c1bacdf15df1f2b4fb7adc9ff71795da90ecf`.

The current graph follows the pose adapter's isolated-reference training semantics while keeping the sparse pose reference small enough for the 16 GiB Radeon target:

```text
OpenPose map
  -> ImageScale (long side <= 512, aspect preserved)
  -> TextEncodeKrea2OstrisEdit (positive + reference)
  -> FluxKontextMultiReferenceLatentMethod(index_timestep_zero)
  -> KSampler positive

same pose map
  -> TextEncodeKrea2OstrisEdit (empty negative + reference)
  -> FluxKontextMultiReferenceLatentMethod(index_timestep_zero)
  -> KSampler negative

Krea 2 MODEL
  -> Krea2OstrisEditModelPatch(kv_cache=true)
  -> LoraLoaderModelOnly(openpose control adapter)
  -> KSampler model
```

Recommended first-gate values are `10 steps`, `CFG 1`, `Euler/simple`, and control strength `0.8–1.0` (default `1.0`). The generated image remains at the requested resolution; only the sparse pose reference is capped at 512 px on its longest side.

#### Target observations

- plain Krea 2 Turbo remains correct with Control guidance disabled;
- after a full machine reboot, two Krea 2 + OpenPose generations completed without the earlier visible control-map/artifact leakage;
- a `Salute · M` template run produced a coherent person but cropped the head/raised arm at the top edge, isolating the next problem to pose framing rather than base Krea generation;
- StableAMD now safe-frame-fits its built-in Pose Depot and interactive-editor maps before submission: non-black skeleton content is detected, uniformly scaled into **82%** of the requested generation aspect, centered on black padding, and sent without interpolation smoothing;
- arbitrary user-uploaded OpenPose maps are deliberately left unchanged so advanced/manual composition is preserved.

The safe-frame change is automated and CI-tested, but the `Salute · M` result still needs a target-machine retest before the framing gate is marked accepted.

#### Earlier full-resolution cached-reference experiment

An earlier experiment enabled `kv_cache=true` while feeding the full-size pose reference without the compact/reference-method corrections above. StableAMD's 900-second application timeout fired, while ComfyUI kept processing and ultimately completed after **27m14s**. That experiment is not the current graph and remains rejected as a usable configuration.

Measured pathological run:

- Krea2TE + WanVAE loaded in about four seconds;
- roughly 24 minutes elapsed before diffusion-model work resumed;
- 8-step sampling then took about 2m35s (~18.7–19.5 s/step);
- total ComfyUI execution: 27m14s.

The current 512 px isolated-reference route is a separate implementation and must be benchmarked from fresh target logs rather than inheriting conclusions from the full-resolution experiment.

StableAMD keeps Qwen3-VL on CPU by default for the accepted 16 GiB profile until a separately measured optimization proves safer/faster.

## Non-regression rule

ControlNet work must not change the accepted behavior of:

- Krea 2 Turbo base generation;
- Krea 2 model-only LoRA;
- Z-Image Turbo base generation;
- Z-Image model-only LoRA;
- Z-Image native inpaint/outpaint;
- classic upscale and Gallery reuse.
