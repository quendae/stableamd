# StableAMD v0.3 forward plan

Last updated: 2026-09-22

StableAMD v0.3 now has **Text-to-SVG v1 target-accepted on RX 6950 XT**. Character Sheet v2 remains implementation-complete but physically unaccepted and stays a separate quality gate. **Image-to-SVG v1 is the active implementation phase with a locked design.**

## Accepted baseline

- Native Windows AMD runtime lifecycle is accepted on RX 6950 XT / 16 GiB.
- SDXL txt2img/img2img/inpaint/outpaint and ordered MultiLoRA remain the compatibility baseline.
- Z-Image Turbo txt2img, ordered model-only LoRA, native inpaint/outpaint, Canny, OpenPose and Depth are accepted/target-tested.
- Krea 2 Turbo FP8 txt2img and model-only LoRA are target-accepted.
- Krea 2 OpenPose, including normal user LoRA + OpenPose, is target-accepted.
- Krea 2 Depth and automatic multi-person DWPose extraction are target-tested.
- Krea 2 whole-image Image Edit is target-accepted.
- RealESRGAN / curated upscale and Gallery reuse remain accepted.
- Long generation requests use serialized async `submit -> poll -> result` transport.
- Text-to-SVG v1 is target-accepted for text-free Icon / Logo mark and Vector Illustration workflows with transparent-background handling and the SVG Gallery lifecycle.

Structural guidance remains provider-first for **Z-Image Turbo and Krea 2 Turbo**. SDXL is deferred for ControlNet-first expansion unless needed for compatibility. The accepted provider surface includes Z-Image Canny plus OpenPose map guidance for Z-Image/Krea paths.

## Character Sheet v2 — active quality gate; physical acceptance remains open

Character Sheet v1 remains only as the explicit `legacy-sequential` comparison path after failing visual acceptance.

The default v2 flow uses Krea 2 Identity Edit v1.2 with the pinned node pack and LoRA, one `1792 x 1024` five-panel base generation, face-only source identity references, guarded local detail passes and non-fatal fallback semantics. BACK never receives face refinement. Heavy Krea passes remain serial and release runtime memory between stages.

The latest architecture specifically avoids reintroducing the head/shoulder identity reference that caused source bleed/ghosting during physical testing. The accepted first detail reference remains face-only; tighter identity correction is limited to appropriate visible-face views.

Character Sheet v2 physical acceptance still requires the same difficult source photographs that exposed v1 weaknesses. Required checks include likeness across visible views, a clean rear view, reduced background/statue leakage, reduced ghost/grid/debris artifacts, repeated-run stability and ordinary Krea Image Edit health afterwards.

Do not tune accepted global Krea txt2img/Image Edit defaults to compensate for a Character Sheet-specific issue.

## Text-to-SVG v1 — target accepted

Text-to-SVG is a dedicated **Vector** product workspace, not a mode inside raster Generate.

### Accepted architecture

```text
Vector request
  -> constrained Z-Image raster generation
  -> release GPU runtime
  -> optional border-connected background removal
  -> pinned VTracer
  -> Clean SVG allow-list sanitizer
  -> PNG preview rendered from the final sanitized SVG
  -> persisted Vector history/Gallery record
```

The Vector request surface remains intentionally small: Prompt, Style, Detail, Colors, Background, Solid color and Seed. It does not expose sampler/scheduler/LoRA/ControlNet controls.

Pinned tooling:

```text
VTracer 1.0.0-alpha.4
resvg_py 0.5.0
```

The final SVG is allow-list sanitized and complexity-bounded before persistence. Active/unsupported content such as script, embedded image, text, external URL/href, event handlers, DTD/entities and unknown namespaces remains rejected.

The first physical RX 6950 XT run exposed one compatibility issue: VTracer emits `version="1.1"` on the root `<svg>`, while the initial sanitizer rejected all root-version attributes. The fix accepts only `1.0` / `1.1` as input metadata and strips the attribute from the canonical Clean SVG. Unknown versions remain rejected. Exact-head Actions #871 is GREEN on commit `5782771a9da306e60ec01caaed5fc40a00165825`: 288 Python tests, 248 Pester tests, package build and artifact upload passed.

### Physical evidence

The agreed v1 A+B scope was exercised on RX 6950 XT on 2026-09-22:

- a two-color transparent fox-head **Icon / Logo mark** passed the Z-Image -> VTracer -> sanitizer -> preview path;
- a transparent 8-color **Vector Illustration** with fox, pine trees and crescent moon produced a usable layered flat-vector composition;
- Download SVG, View source, Reuse and Delete were all confirmed working by the user.

This closes the v1 physical gate. The full evidence record is `docs/v0.3-text-to-svg-test.md`.

Additional prompt diversity, Detailed/16-color stress runs, repeated complexity measurements and longer Krea/Z-Image regression sessions remain useful non-blocking QA.

## Image-to-SVG v1 — active implementation phase

Locked design:

- `docs/superpowers/specs/2026-09-22-image-to-svg-v1-design.md`

Image-to-SVG extends the existing Vector workspace instead of creating a second vector product or SVG stack.

### Source contract

Supported source handoff:

1. local image upload through a managed image source;
2. raster Gallery `Convert to SVG`;
3. current successful Generate / Image Edit result without manual download/re-upload.

All source resolution remains server-owned. Browser-provided arbitrary filesystem paths are invalid. Gallery/current sources are references and are not deleted with derived SVG assets.

### Locked modes

```text
Artwork
Photo / Direct
Photo / Stylized / Preserve
Photo / Stylized / Creative
```

`Artwork`, `Photo / Direct`, and `Photo / Stylized / Preserve` are deterministic local workflows.

`Photo / Stylized / Creative` is optional and provider-aware. Krea 2 whole-image Image Edit is the first implementation. If Krea is unavailable, only Creative is disabled.

### Main UI

The default Image-to-SVG form exposes:

- Source;
- Mode / Stylization;
- Detail: Simple / Medium / Detailed;
- Colors: Auto / 2 / 4 / 8 / 16;
- Background: Preserve / Transparent;
- Crop: Preserve canvas / Auto-trim / Manual crop;
- Convert to SVG.

Advanced remains collapsed by default and exposes normalized controls:

- Smoothing;
- Edge strength;
- Denoise;
- Posterize;
- Background tolerance.

Background and canvas default to **Preserve**. Existing alpha is preserved. Transparent background removal reuses/generalizes the accepted border-connected logic rather than deleting matching colors globally.

### Pipeline by mode

Artwork:

```text
managed source -> crop -> artwork preprocessing -> optional background removal -> VTracer -> sanitizer -> preview -> Gallery
```

Photo Direct:

```text
managed source -> crop -> photo normalization -> deterministic simplification -> optional background removal -> VTracer -> sanitizer -> preview -> Gallery
```

Photo Stylized Preserve:

```text
managed source -> crop -> stronger deterministic local stylization -> optional background removal -> VTracer -> sanitizer -> preview -> Gallery
```

Photo Stylized Creative:

```text
managed source -> crop -> Krea Image Edit vector-style raster -> release GPU runtime -> local preprocessing -> VTracer -> sanitizer -> preview -> Gallery
```

### Runtime contract

Local modes reuse the generic async job transport but should not hold the GPU generation lock. Expensive local vectorization is serialized independently.

Creative holds the existing generation/GPU lock only during the Krea Image Edit stage, releases GPU runtime, then continues locally.

The accepted VTracer `1.0.0-alpha.4`, `resvg_py==0.5.0`, Clean SVG sanitizer, safe source JSON endpoint and ownership-aware deletion remain shared unchanged unless an evidence-backed defect requires a bounded fix.

### Implementation order

1. request validation + mode presets;
2. managed source resolution for upload/Gallery/current;
3. deterministic preprocessing, alpha preservation, crop and Auto-trim;
4. transparent background removal/tolerance;
5. local Artwork / Direct / Preserve orchestration through the shared Vector stack;
6. Creative provider adapter using Krea Image Edit with GPU release before tracing;
7. Vector frontend Image-to-SVG form + source preview/manual crop;
8. Gallery/current `Convert to SVG` handoff + Reuse behavior;
9. packaging/import regression;
10. target RX 6950 XT worksheet and physical acceptance.

Every behavior change follows RED -> GREEN. Image-to-SVG remains physically unaccepted until the full target worksheet passes.

## Immediate execution order

1. Implement Image-to-SVG v1 against the locked design and keep Text-to-SVG behavior unchanged.
2. Run full automated verification after each logical task and preserve lazy heavy imports.
3. Pull the exact GREEN head onto the RX 6950 XT and run Image-to-SVG acceptance for Artwork, Direct, Preserve and Creative plus upload/Gallery/current handoff.
4. Fix only evidence-backed Image-to-SVG defects found by physical testing.
5. Continue the separate Character Sheet v2 physical quality/stability gate.
6. After Image-to-SVG, evaluate an infographic-oriented provider/workflow prioritizing text rendering, layout and diagram reliability.

## Infographic-oriented generation after SVG

This should be treated as a separate provider/tool contract, not another toggle on the diffusion form. Evaluation should prioritize:

- text fidelity and spelling;
- alignment/layout;
- arrows/connectors;
- tables and diagram structure;
- exportability/editability;
- predictable aspect/layout controls.

## Later roadmap

### Gaussian Splatting / 3D

Post-v0.3 candidate: local Image(s) -> Gaussian Splat with browser preview/export. FreeSplatter / Vulkan remains the preferred research direction.

### Video

Video remains later than current image/edit/vector work and needs its own queue UX, asset management and memory acceptance. MiniMax H3 remains a candidate to benchmark later; it is not part of the current v0.3 acceptance scope.

## Explicit non-goals for the current pass

- no SDXL-first ControlNet expansion;
- no fake Canny/Depth/Pose toggles sharing one graph;
- no unpinned/license-unknown custom-node installs;
- no weakening of the Clean SVG allow-list to make traces pass;
- no raw arbitrary SVG browser serving;
- no speculative throughput changes that destabilize accepted Krea/Z-Image paths;
- no Masked Krea editing in this wave;
- no Krea Image Edit + Control composition in this wave;
- no semantic/native vector model or Rich SVG expansion inside Image-to-SVG v1;
- no OCR/text-fidelity promise for Image-to-SVG v1.
