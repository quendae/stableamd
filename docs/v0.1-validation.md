# StableAMD v0.1 validation

StableAMD v0.1 is **hardware-accepted on AMD Radeon RX 6950 XT 16 GiB (`gfx1030`)**. On 2026-09-11 the clean source package installed its private runtime from scratch, passed the native Radeon FP16 compute gate, launched the managed ComfyUI backend and StableAMD application, discovered existing checkpoints without copying them, generated an SDXL 1024x1024 image through the product flow, and displayed the result in Gallery.

## Accepted reference stack

- GPU: AMD Radeon RX 6950 XT 16 GiB;
- target: `gfx1030` / `device-gfx1030`;
- Python: `3.12.10`, private **CPython NuGet x64** distribution;
- PyTorch: `2.13.0+rocm10.1.0a20260822`;
- torchvision: `0.28.0+rocm10.1.0a20260822`;
- torchaudio: `2.11.0+rocm10.1.0a20260822`;
- TheRock package source: `https://rocm.nightlies.amd.com/whl-multi-arch/`;
- ComfyUI: `0.35.0`, commit `40c4fcdf513a4523e39d54a9d391908af8df8171`;
- compatibility reference: Stable Diffusion XL 1.0 base;
- generation: `1024x1024`, 20 steps, batch 1;
- feasibility reference generation time: about 102 seconds;
- feasibility reference peak VRAM: about 14 GiB.

The machine-readable release lock and acceptance state are stored in `config/runtime-lock.v0.1.json`.

## Automated acceptance

The GitHub Actions suite covers the non-GPU contracts:

- PowerShell syntax and Python helper compilation;
- StableAMD local API tests;
- runtime lifecycle and deterministic bootstrap contracts;
- exact locked runtime versions;
- model discovery, external model roots, local import and Hugging Face download contracts;
- SDXL workflow, generated-output correlation and generation history contracts;
- frontend/API integration contracts;
- one-click launcher contracts;
- release packaging contract;
- a plan-only clean-package build with no GPU runtime download.

The release package is source-only by design. It does not ship `.runtime/`, models, generated images, diagnostics, tests, or Git metadata.

## Runtime bootstrap design

When the runtime is absent, `scripts/Install-StableAMDRuntime.ps1`:

1. reads the versions in `config/runtime-lock.v0.1.json`;
2. detects the supported `gfx1030` Radeon target before the large download;
3. downloads the official CPython 3.12.10 NuGet x64 package and extracts its `tools` runtime directly under StableAMD;
4. verifies that the private interpreter has a working bundled `pip`;
5. installs the exact TheRock torch / torchvision / torchaudio versions for `device-gfx1030`;
6. downloads ComfyUI by immutable commit rather than following a moving branch;
7. installs ComfyUI dependencies without allowing generic PyPI torch packages to replace the locked AMD stack;
8. imports torch, torchvision and torchaudio;
9. runs the real FP16 Radeon compute probe;
10. writes `.runtime/stableamd/runtime-install.json` only after compute validation passes.

The CPython NuGet distribution is intentionally side-by-side and does not register a normal Windows Python installation. This allows StableAMD and the isolated acceptance harness to create independent private runtimes repeatedly.

## Clean-package runtime acceptance — PASSED

The isolated package harness was run on the physical RX 6950 XT on 2026-09-11. The successful run printed:

```text
STABLEAMD CLEAN-PACKAGE RUNTIME ACCEPTANCE PASSED.
```

The successful acceptance report was `acceptance-package-20260911-210243.json`. The run verified:

- a newly built source-only package;
- a fresh private CPython NuGet / TheRock / ComfyUI runtime inside the isolated package copy;
- the real Radeon FP16 compute gate;
- managed ComfyUI startup;
- StableAMD application startup and `/api/health`;
- healthy managed backend status;
- model API access;
- teardown of the isolated successful runtime after the test.

The harness remains available for repeatability:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Test-StableAMDPackage.ps1
```

Use `-KeepRuntime` to retain a successful isolated runtime, or `-PlanOnly` to validate the locked installation plan without downloading the GPU runtime.

## Product-flow acceptance — PASSED

The normal StableAMD product flow was then exercised on the same RX 6950 XT:

- existing model folders were discovered in place, including the existing SwarmUI Stable Diffusion library;
- adding/scanning external model folders required no multi-gigabyte checkpoint copy;
- an SDXL checkpoint was selected from the StableAMD Generate page;
- StableAMD submitted its internal fixed SDXL workflow to managed ComfyUI;
- a 1024x1024 image was generated successfully on the Radeon GPU;
- generated-output fallback correlation handled a ComfyUI history response that omitted `SaveImage` image metadata;
- the image and generation metadata appeared correctly in Gallery.

The accepted user path is therefore **Models -> Generate -> Gallery** without opening the ComfyUI node interface.

## Remaining secondary checks

These are useful regression/manual checks but are not blockers for the RX 6950 XT v0.1 hardware acceptance already recorded above:

- exercise a real authenticated/private Hugging Face download if such a model is needed; public/local model paths are already covered by tests and the accepted external-folder flow;
- continue UI polish of Settings and Diagnostics;
- repeat stop/relaunch lifecycle checks when backend lifecycle code changes;
- repeat the clean-package acceptance whenever runtime-lock versions change.

No acceptance is implied for Radeon models other than RX 6950 XT / `gfx1030`; additional GPU targets need their own runtime and generation validation.

## Release package check

From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Build-StableAMDPackage.ps1
```

Expected outputs:

```text
dist\StableAMD-0.1.0\
dist\StableAMD-0.1.0.zip
```

The ZIP intentionally does not bundle the multi-gigabyte ROCm/PyTorch runtime or model checkpoints. First launch installs the pinned private runtime when it is absent.

## Release decision

For the **RX 6950 XT / gfx1030 target**, the v0.1 hardware gate is satisfied: clean-package bootstrap, native FP16 Radeon compute, managed backend/application startup, external model discovery, SDXL 1024x1024 product generation, persistence, and Gallery display have all been exercised successfully. CI remains the gate for source-level regressions, and any change to the locked runtime stack requires repeating target-machine acceptance.
