# StableAMD v0.1 validation

This document separates what has already been proven on the RX 6950 XT from what still has to be re-run as the final product acceptance pass.

## Proven foundation

The feasibility spike already proved native Windows GPU generation on **AMD Radeon RX 6950 XT 16 GiB (`gfx1030`)** through the TheRock multi-arch runtime, PyTorch ROCm and ComfyUI.

Validated reference stack:

- GPU: AMD Radeon RX 6950 XT 16 GiB;
- target: `gfx1030` / `device-gfx1030`;
- PyTorch: `2.13.0+rocm10.1.0a20260822`;
- ComfyUI: `0.35.0`;
- reference model: Stable Diffusion XL 1.0 base;
- generation: `1024x1024`, 20 steps, batch 1;
- observed generation time: about 102 seconds;
- observed peak VRAM: about 14 GiB.

The tested TheRock package source is `https://rocm.nightlies.amd.com/whl-multi-arch/`. The machine-readable release lock is `config/runtime-lock.v0.1.json`.

## Automated acceptance

The GitHub Actions suite must remain green for all non-GPU contracts:

- PowerShell syntax;
- Python helper compilation;
- StableAMD application API tests;
- runtime lifecycle contracts;
- model discovery/import/download contracts;
- SDXL workflow and history contracts;
- frontend/API integration contracts;
- one-click launcher contracts;
- release packaging contract.

The release package is source-only by design. It must not contain `.runtime/`, models, generated images, diagnostics, tests, or Git metadata.

## Final RX 6950 XT product acceptance

The following checks are required on the actual Radeon machine before calling v0.1 a clean-machine release:

- [ ] **clean-machine runtime install/reuse — pending**. Confirm that a fresh StableAMD checkout/package can prepare or reuse the tested TheRock + ComfyUI runtime without hand-editing Python packages or environment variables.
- [ ] Start StableAMD with `Start-StableAMD.cmd` and confirm the application opens on loopback only.
- [ ] Confirm Diagnostics identifies RX 6950 XT / `gfx1030` and reports a healthy managed backend.
- [ ] Confirm `scripts/Get-StableAMDStatus.ps1` reports the managed backend as running and exposes the Radeon device.
- [ ] Import a valid SDXL `.safetensors` checkpoint through Models and confirm it appears in the model list.
- [ ] Download or register a Hugging Face checkpoint through the product model flow and verify structural validation.
- [ ] Generate one default SDXL image through the StableAMD Generate page at `1024x1024`, 20 steps, batch 1, without opening the ComfyUI node UI.
- [ ] Confirm the generated image appears in Gallery with prompt, model, dimensions, seed and settings metadata.
- [ ] Exercise Settings and Diagnostics and confirm failures are reported as product-level messages rather than raw node errors.
- [ ] Stop the managed backend with `scripts/Stop-StableAMD.ps1` and verify only the recorded StableAMD process is stopped.
- [ ] Relaunch and confirm an existing healthy service can be reused safely.

## Release package check

From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Build-StableAMDPackage.ps1
```

Expected outputs:

```text
dist\StableAMD-0.1.0\
dist\StableAMD-0.1.0.zip
```

The ZIP intentionally does **not** bundle the multi-gigabyte ROCm/PyTorch runtime or model checkpoints. Runtime installation/reuse is the remaining clean-machine acceptance gate and is still marked **pending** until it is exercised end-to-end on the target Radeon machine.

## Release decision

v0.1 can be called hardware-accepted only when the automated suite is green and every item in the final RX 6950 XT product acceptance section has been run successfully on the target machine. A successful earlier feasibility generation is strong evidence for the compute path, but it does not substitute for the final packaged clean-machine test.
