# StableAMD v0.3 — Z-Image native edit target test

This gate validates provider-native Z-Image inpaint/outpaint on the accepted RX 6950 XT / Windows stack without changing the proven Z-Image txt2img + LoRA path.

## Why this path is real

The pinned ComfyUI commit `40c4fcdf513a4523e39d54a9d391908af8df8171` contains the native `ModelPatchLoader` and `ZImageFunControlnet` nodes. `ZImageFunControlnet` accepts `inpaint_image` plus `mask`, so StableAMD can use the same PNG-alpha inpaint transport already used by the Gallery editor instead of pretending a generic SDXL graph is Z-Image editing.

Krea 2 stays capability-gated for editing: the pinned local Krea 2 Turbo path does not currently expose an equivalent validated local edit workflow.

## Required model patch

Install the official Alibaba PAI patch:

- repository: `alibaba-pai/Z-Image-Turbo-Fun-Controlnet-Union`
- file: `Z-Image-Turbo-Fun-Controlnet-Union.safetensors`
- license: Apache-2.0
- SHA-256: `86c085c0d7853f12ce5183499934b54d08371c60f549c5a6b20615cd23989388`

StableAMD managed destination:

```text
.runtime/stableamd/models/model_patches/Z-Image-Turbo-Fun-Controlnet-Union.safetensors
```

The launcher now exposes the managed `model_patches` directory to ComfyUI. Existing user configs do not need to be regenerated.

Official download URL:

```text
https://huggingface.co/alibaba-pai/Z-Image-Turbo-Fun-Controlnet-Union/resolve/main/Z-Image-Turbo-Fun-Controlnet-Union.safetensors
```

After the file is present, restart StableAMD completely so ComfyUI registers `ModelPatchLoader` choices.

## Capability behavior

StableAMD does **not** statically advertise Z-Image inpaint. On `/api/model-support`, `inpaint` changes from `planned` to `supported` only when ComfyUI actually exposes the official Fun Control Union patch.

That means Gallery Inpaint/Outpaint can keep the original Z-Image model only when the native edit dependency is genuinely available. If the patch is absent, the existing capability-driven fallback remains unchanged.

## First target test

1. Start StableAMD normally with the accepted default RX 6950 XT profile.
2. Confirm ordinary Z-Image txt2img still works before editing.
3. Generate a simple Z-Image source at 1024-class resolution.
4. From Gallery choose **Inpaint**, paint one clearly bounded object/region, keep LoRA disabled and generate with a detailed replacement prompt.
5. From the same source choose **Outpaint**, use a modest expansion and generate once.
6. Run another ordinary Z-Image txt2img afterwards to prove the edit provider did not destabilize the accepted base path.

The first native edit workflow deliberately uses:

- base Z-Image Turbo three-file bundle;
- `ModelPatchLoader` with the Fun Control Union patch;
- `ZImageFunControlnet` with the source RGB image and PNG-alpha mask;
- `ModelSamplingAuraFlow` shift `3.0`;
- `8 steps / CFG 1 / res_multistep / simple` unless the request explicitly carries another accepted Z-Image setting;
- edit denoise fixed to `1.0` for the initial target gate;
- control strength `1.0`;
- no LoRA during the first native-edit acceptance run.

Outpaint reuses the same native inpaint path plus the existing `editContext` source/margin metadata.

## Acceptance evidence to capture

- result image for one inpaint and one outpaint;
- the backend log around `ModelPatchLoader` / `ZImageFunControlnet` execution;
- whether the untouched region remains acceptably stable;
- whether the following normal Z-Image txt2img still succeeds;
- approximate generation time and any VRAM/runtime warnings.

Do not mark Z-Image native editing accepted until those target-machine checks pass.
