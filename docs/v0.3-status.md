# StableAMD v0.3 status

Last updated: 2026-09-13

StableAMD v0.3 is the active development line on `feat/stableamd-v0.3` / draft PR #4. The target machine is an AMD Radeon RX 6950 XT 16 GiB (`gfx1030`) on Windows using the pinned TheRock/ROCm + PyTorch + ComfyUI stack first accepted in v0.1.

## Accepted on the target machine

### Core runtime

- native Windows AMD execution on RX 6950 XT / `gfx1030`;
- private CPython 3.12.10 runtime;
- PyTorch `2.13.0+rocm10.1.0a20260822`;
- torchvision `0.28.0+rocm10.1.0a20260822`;
- torchaudio `2.11.0+rocm10.1.0a20260822`;
- ComfyUI 0.35.0 pinned to `40c4fcdf513a4523e39d54a9d391908af8df8171`;
- managed loopback backend/application lifecycle, persistent history/gallery, live timestamped diagnostics and clean teardown.

### SDXL

- txt2img;
- img2img;
- inpainting execution;
- sampler/scheduler metadata and generation presets;
- ordered MultiLoRA for supported SDXL workflows;
- external checkpoint and LoRA roots.

### Z-Image Turbo

The official three-file ComfyUI package is supported:

- `z_image_turbo_bf16.safetensors`;
- `qwen_3_4b.safetensors`;
- `ae.safetensors`.

The dedicated provider uses the official-style Lumina2/AuraFlow graph and has passed repeated target-machine generation tests.

Recommended RX 6950 XT 16 GiB memory profile:

```powershell
.\Start-StableAMD.cmd -DisableDynamicVram -LowVram -CacheClassic
```

Observed warm behavior at the 1024-class / 8-step recommended profile:

- Qwen text encoder stays on CPU;
- Lumina2 is partially resident in GPU memory, approximately 8.0 GiB loaded and 3.7 GiB offloaded in the stable warm state;
- sampler cadence is approximately `2.36-2.38 s/it`;
- warm generation with reused prompt conditioning is approximately `25-26 s`;
- a changed prompt is approximately `32 s` in the tested warm session;
- cold first generation is substantially slower because model/text-encoder initialization is required.

`HighVram` is not recommended for this 16 GiB card: full Lumina2 residency was much slower in repeated tests because it left insufficient practical headroom for execution.

Z-Image generation profiles now include four size tiers (`Small`, `1024`, `1280`, `1536`) and common portrait/landscape ratios. The 1024 tier remains the recommended default. Fast/recommended/quality step presets keep the proven `res_multistep + simple + CFG 1` path.

## LoRA compatibility

StableAMD now treats LoRA compatibility as model-family-aware metadata instead of assuming that every discovered adapter can be used everywhere.

- managed LoRA folders are grouped by family (`shared`, `sd15`, `sdxl`, `sd3`, `z-image`, `flux`, `krea`);
- safetensors metadata is inspected without loading tensor payloads;
- fallback classification uses managed folder and then filename hints;
- known cross-family mismatches are blocked server-side;
- unknown adapters remain explicitly `unknown` instead of being guessed compatible;
- the UI hides incompatible adapters by default and can show them for inspection.

LoRA execution support remains workflow-specific. In particular, Z-Image LoRA execution is still planned even though the catalog can classify Z-Image adapters.

## Post-generation tools

Gallery items now expose actions for:

- Upscale;
- Img2Img;
- Inpaint;
- Outpaint.

Img2Img and Inpaint hand off the generated image into the existing editors. Outpaint currently has the handoff/editor shell; full outpaint geometry/execution polish remains a follow-up item.

### Classic model upscale

The first upscale provider uses stock ComfyUI nodes:

```text
LoadImage -> UpscaleModelLoader -> ImageUpscaleWithModel -> SaveImage
```

StableAMD exposes `.runtime/stableamd/models/upscale_models` to ComfyUI and supports common ESRGAN-family `.pth`/`.safetensors` models such as RealESRGAN and 4x-UltraSharp.

Current target status:

- ComfyUI correctly discovers `RealESRGAN_x2plus.pth` from the managed upscale folder;
- StableAMD now understands the current ComfyUI `COMBO` + `options` object-info contract;
- the generic service `RepoRoot` parameter mismatch in `Build-StableAmdUpscaleWorkflow.ps1` has been fixed;
- CI is green after both regressions;
- **the next target-machine gate is the first successful end-to-end upscale execution after the `RepoRoot` fix.**
