# StableAMD v0.3 status

Last updated: 2026-09-14

StableAMD v0.3 is the active development line on `feat/stableamd-v0.3` / draft PR #4. The target machine is an AMD Radeon RX 6950 XT 16 GiB (`gfx1030`) on Windows using the pinned TheRock/ROCm + PyTorch + ComfyUI stack first accepted in v0.1.

### Z-Image Turbo

The official three-file ComfyUI package is supported:

- `z_image_turbo_bf16.safetensors`;
- `qwen_3_4b.safetensors`;
- `ae.safetensors`.

The dedicated provider uses the official-style Lumina2/AuraFlow graph and has passed repeated target-machine generation tests.

Recommended RX 6950 XT 16 GiB memory profile:

```powershell
.\Start-StableAMD.cmd -DisableDynamicVram -LowVram -CacheClassic
```

Observed warm behavior at the 1024-class / 8-step recommended profile:

- Qwen text encoder stays on CPU;
- Lumina2 is partially resident in GPU memory, approximately 8.0 GiB loaded and 3.7 GiB offloaded in the stable warm state;
- sampler cadence is approximately `2.36-2.38 s/it`;
- warm generation with reused prompt conditioning is approximately `25-26 s`;
- a changed prompt is approximately `32 s` in the tested warm session;
- cold first generation is substantially slower because model/text-encoder initialization is required.

`HighVram` is not recommended for this 16 GiB card. Z-Image generation profiles include `Small`, `1024`, `1280` and `1536` size tiers plus common portrait/landscape ratios. The 1024 tier remains the recommended default and the proven sampler path remains `res_multistep + simple + CFG 1`.

## LoRA compatibility

StableAMD treats LoRA compatibility as model-family-aware metadata instead of assuming that every discovered adapter can be used everywhere.

- managed LoRA folders are grouped by family (`shared`, `sd15`, `sdxl`, `sd3`, `z-image`, `flux`, `krea`);
- safetensors metadata is inspected without loading tensor payloads;
- fallback classification uses managed folder and then filename hints;
- known cross-family mismatches are blocked server-side;
- unknown adapters remain explicitly `unknown` instead of being guessed compatible;
- the UI hides incompatible adapters by default and can show them for inspection.

SDXL LoRA/MultiLoRA execution is implemented. Z-Image LoRA execution remains planned even though the catalog can classify Z-Image adapters.

## Generate UI compactness pass

Implemented on the branch; target visual/interaction acceptance is pending.

- generation mode, model and preset are grouped before the prompt;
- model-aware Size and Ratio controls stay compact;
- manual Width/Height are shown only for Custom size;
- Seed, Sampler, Scheduler, Steps and CFG share one dense row;
- Negative prompt is hidden for model families whose StableAMD workflow does not use it, including Z-Image;
- LoRA stack is the primary adapter UI;
- one visible Strength value controls model + CLIP by default, with a per-LoRA CLIP override available only when needed;
- compact icon-led actions are used in Gallery without making the UI icon-only.

The compact layer rearranges existing controls rather than replacing the proven provider APIs.

## Gallery and post-generation tools

Gallery items expose:

- Upscale;
- Img2Img;
- Inpaint;
- Outpaint;
- Delete.

Img2Img/Inpaint handoff uses the existing editors. Delete removes the history record and its managed output image when present. Upscale records are labelled as upscale operations instead of `Unknown model`.

Outpaint has the image handoff, asymmetric margin controls and expanded-canvas/mask preparation; final target acceptance and additional polish remain pending.

### Exact 2x / 4x / 8x planner

Implemented on the branch; target execution acceptance is pending.

StableAMD now treats `2x`, `4x` and `8x` as requested final factors rather than blindly exposing a model's native scale.

- a native matching model is preferred when available;
- otherwise the shortest exact chain is used;
- with only `RealESRGAN_x2plus`, 4x becomes `2x -> 2x` and 8x becomes `2x -> 2x -> 2x`;
- with x4 and x2 models installed, 8x can use a two-pass `4x * 2x` chain;
- impossible exact combinations are rejected before execution;
- intermediate chain images are not added to Gallery history;
- Gallery manual Upscale now has Target `2x / 4x / 8x` plus `Auto` or an explicit preferred model;
- Generate has a shared `Upscale after` control for txt2img/img2img/inpaint/outpaint with `Off / 2x / 4x / 8x`;
- the Generate UI previews target dimensions and warns for unusually large outputs.

SeedVR2 remains a separate optional/experimental provider and is not part of this classic chaining logic.
